# Final submission checklist

Use this immediately before applying.

## Application assets

- [ ] One-link proof opens on desktop and phone.
- [ ] GitHub Pages deployment is green on the final `main` commit.
- [ ] The visible headline says **Junior Intelligence Analyst**, not a broader AI role.
- [ ] CV uses the targeted SafeTrace bullets from `CV_TAILORING.md`.
- [ ] Application message contains the final public proof URL.
- [ ] GitHub profile / portfolio links point to working public pages.

## Claims sanity check

- [ ] Say **synthetic benchmark** every time the 95/100 or 100/100 scores are mentioned.
- [ ] Do not imply SafeTrace has been validated on Venatic client work or private data.
- [ ] Do not imply the live Venatic boundary establishes shareholders or UBOs; it explicitly does not.
- [ ] Do not call the project a replacement for analysts.
- [ ] Do not present yourself as a senior intelligence professional or “Product Architect”; present the article’s loop as the way you directed the build.

## 30-second application test

A reviewer should understand these four things without scrolling far:

1. **Role:** Junior Intelligence Analyst.
2. **Problem:** fragmented corporate evidence and difficult analytical judgment.
3. **Proof:** a 28-source synthetic case with ownership, sanctions, assets and research triage.
4. **Measured result:** 95/100 blind → 100/100 after five targeted sources, zero critical failures.

If any of those is unclear, fix the page before submitting.

## Interview readiness

- [ ] Can explain the sanctions false positive in 30 seconds.
- [ ] Can explain why the nominee remains unresolved.
- [ ] Can explain why S27 is repetition, not corroboration.
- [ ] Can explain the five selected optional sources and why they beat the alternatives.
- [ ] Can name at least three bugs the verification loop caught.
- [ ] Can explain which conclusions remain human-owned.
- [ ] Can say what you would learn from Venatic before changing their workflow.

## Send

Recommended package:

1. tailored CV;
2. short application message;
3. **one proof-of-work URL**.

Do not attach a pile of extra project documents unless requested. The proof page links to the deeper material for anyone who wants it.
